# 反向护甲融合 · 0.1.8

在普通铁砧左侧放其他模组／原版护甲，右侧放同部位的Ars护甲。消耗两件装备及1级经验，保留左侧物品身份、外观、耐久、附魔和原生能力，加入右侧的原生丝线数据、已装丝线、丝线状态和当前护甲升级等阶。新结果仍可在原生改造台装卸丝线，继续使用原生护甲升级配方。

`armor_fusion.reverse_enabled = true`默认开启，受`armor_fusion.enabled`总开关约束。反向融合不受正向属性黑名单／自动兼容开关限制；来源基础属性仅通过下述两个专用策略处理，不走正向的通用modifier转移。关闭制作不影响既有装备。

## 防御与魔力属性

两个独立开关均默认开启，作用于新旧融合结果，运行时修改后需重新穿戴：

- `armor_fusion.reverse_uses_ars_defense`：移除主体物品的护甲值／护甲韧性属性修饰，改用Ars来源护甲的材质基础防御。如果启用了`ars_armor_toughness.enabled`，还会按融合结果当前的装备等阶追加韧性。丝线效果随后单独计算，不会重复复制韧性丝线。关闭后恢复主体原本的防御属性。
- `armor_fusion.reverse_transfers_ars_mana`：附加Ars来源护甲自身的最大魔力和魔力回复属性。复制来源快照作为临时读取栈，设置为融合结果当前等阶并清空已装丝线，读取原生Ars属性的数值和运算方式。主体已有的魔力属性保留，丝线的魔力加成仍单独生效一次。关闭后移除这部分来源基础加成，保留丝线。

来源护甲快照不会被修改，主体物品的属性组件／NBT也不被永久抹除；替换发生在带反向融合标记的栈的属性查询中。击退抗性等其他主体属性不受防御替换影响。不会额外转移Iron的独立魔力属性、法术强度或来源护甲的全部其他属性。

## 边界

- 两侧须为同部位、单件护甲；主体使用标准ArmorItem。已有原生Ars丝线能力的主体不能再接受一套。
- 正反两向都拒绝已经融合过的装备，不能把融合结果继续作主体或材料嵌套。
- 防御及基础Mana／回蓝按上述开关处理。不移植没有修复丝线时的被动修复或猪灵中立。修复丝线仍按原生费用修复融合装备。
- 所有权在具体ItemStack上，不给同物品ID的其他护甲提供槽位，不把其他模组护甲全局伪装为Ars护甲。
- 保留主体原能力依靠保留原物品及其使用逻辑；原模组将装备升级成另一个物品时，仍由其配方决定是否携带附加数据，本次不拦截所有外部升级配方。
- 穿戴玩家的丝线tick已接入；没有承诺给所有模组NPC增加玩家限定的丝线持续效果。丝线自身的原生适用条件保持不变。

## 实现

共享规则位于`armor/ReverseArmorFusion`；组件／NBT、事件和原生数据接线位于两端的`platform/ReverseArmorPlatform`。Iron依旧可选，本功能不依赖Iron或Conflux。

NeoForge使用独立`ars_fusion:reverse_armor_fusion`不可变容器组件保存Ars来源快照，原生`ARMOR_PERKS`组件保存正在使用的丝线状态。只对带标记的栈改写`PerkRegistry.getPerkProvider(ItemStack)`查询，槽位矩阵来自原Ars物品注册；原生改造台和升级配方继续读写真正的原生组件。

Forge使用同名NBT保存来源快照，只有原生`an_stack_perks`标签被复制到主体。只对带标记的栈接入`PerkUtil.getPerkHolder`，返回绑定主体的原生ArmorPerkHolder子类；槽位按来源实际注册provider和当前等阶读取。原生的NBT更新、改造台与升级配方不另实现。

属性事件在LOWEST优先级处理防御替换、可选来源基础魔力属性和原生丝线modifier。来源魔力属性以稳定、按部位区分的Fusion ID转移，避免覆盖主体已有modifier。玩家穿戴tick委托给原生ITickablePerk；修复丝线使用原生RepairingPerk。伤害／施法／装备切换等丝线回调由Ars已有PerkEvents和PerkUtil读取。未调用整件Ars护甲的tick。

正向融合的Ars身份判断排除反向标记，防止其他模组护甲得到丝线后被误认成正向属性融合结果；原正向融合、历史Iron组件和法术容器迁移路径保留。

## 验证

0.1.7已有原生路径回归用例：铁砧消耗、错部位和嵌套拒绝、丝线与等阶保留、同ID未融合物品不受影响、存档／网络序列化、原生升级、改造台拆卸和重新安装。原来的“不复制基础Mana”用例明确关闭新开关，继续验证兼容行为。

0.1.8新增共享防御／魔力策略用例：通过真实属性事件比较Ars来源、反向融合结果及未融合主体；核对防御替换、丝线只算一次、其他属性保留、开关相互独立、既有融合切换配置、升级后的实时等阶，以及魔力modifier运算方式。编译这些用例不等于运行通过。

本批按用户减少测试／内存占用的偏好，只进行双端主代码和回归源码编译、发行与源码JAR打包、Forge重混淆／refmap验证及发布包检查。没有启动游戏、服务端或GameTest。客户端改造台渲染和复杂护甲附属的特殊升级仍需实际游戏验证。产物哈希和实际构建结果见`reverse-armor-0.1.8-build.json`。本批没有实现讨论中的四／五级装备或槽位。
